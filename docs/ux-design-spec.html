Writing-First Experience Redesign

UX strategy for GH#118 — interactive design spec for all 5 implementation phases.

Core Problem
3+ clicks
before a returning writer reaches their scene
Design Direction
Editor = Home
every decision routes back to writing
AI Direction
In the editor
not a competing sidebar tab

Design Principles

1
Writing is the center of gravity. The editor is home. Every default route and post-action redirect drops the writer into a scene.
2
Context follows the cursor. Show what's relevant to this scene — not master lists of all characters, all threads, all time.
3
Progressive complexity. A fresh project needs a blank scene. Features emerge as the manuscript grows.
4
Show momentum, not metrics. No streaks, no badges. A visual record that the work is happening.
5
AI assists the writing, not the interface. Select text → get options. Contextual prompts. Never a generic chatbot sidebar.

Key Changes Annotated

1
Context tab — default active when any scene is open. Shows characters (in-scene vs others), current location, active plotlines. Pulls from relationship data — no new API needed.
2
@-mentions — type @ to trigger autocomplete, grouped by type. Inserting a mention auto-creates the scene→object relationship. Hover for tooltip, click to open panel. Tiptap ProseMirror extension.
3
Beats in outline tree — scene beats parsed from <!-- beat: ... --> comments, shown as indented "→ Beat" items. Thread dots (blue=advancing / amber=mentioned / gray=dormant) per scene.
4
Session word counter in footer — "Session: 340 words in 24 min · 850 wph". Detects start on first keystroke, resets after 5 min inactivity. Preview of Phase 4 session tracking.

Key Changes Annotated

1
Progress route at /project/[id]/progress. Reads scene status field and word counts — no new data model except for WritingSession for session tracking.
2

Key Changes Annotated

1
Consistency alerts — background AI analysis compares story object descriptions across scenes. Alerts appear as highlighted text with inline callouts (not blocking). Actions train the system.
2
Alert counter in toolbar — "⚠ 2 alerts" pill. Clicking navigates to first alert in document. Non-intrusive until the writer wants to address them.
3
Plot thread dots — reuse relationship data from Phase 2. New: "dormant since Ch. N" warnings for threads that haven't appeared in many scenes.
4
Phase 5 requires new infrastructure: background processing pipeline for consistency analysis, ConsistencyAlert table. Plan for post-Phase 4 implementation only.
